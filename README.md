# CampusTalk · 校园即时通讯系统

面向高校班级与社团的 Web 即时通讯系统：**熟人聊天（私聊 / 群聊）为主轴**，完整覆盖八项基础功能；以**校园身份（学号 / 院系 / 班级）**与**兴趣频道（帖子 / 评论 / 点赞内容层）**作为差异化切口，并配套独立的管理后台与内容治理能力。

单人开发，演示环境仅在本机 `localhost` 运行。

## 二、技术栈

| 层 | 选型 |
|---|---|
| 表现层 | Vue 3 + Vite + Pinia + Vue Router（30 个手写组件，无 UI 库；设计令牌参考腾讯 TDesign 开源设计规范） |
| 接口层 | FastAPI：REST 管「会失败的操作」，原生 WebSocket 只管实时投递，两者不混用 |
| 业务层 | Python 六个域（身份 / 关系 / 会话 / 消息 / 内容 / 机器人），全系统唯一判断权限的地方 |
| 数据层 | SQLAlchemy 2.0 async + aiomysql + MySQL（库名 `campustalk`，`utf8mb4`）；文件落 `uploads/` |

**技术栈边界**：Redis 只做 Pub/Sub 广播总线（瞬态通道，不存持久数据，E-R 与表结构不受影响；连接表仍进程本地，跨进程送达由总线兜底）；**明确不引入**：消息队列、Nginx、对象存储、Docker Compose、微服务拆分——每多一个中间件就多一个「演示现场起不来」的风险点。Redis 为硬依赖，Windows 本机由 Redis 5.0.14.1 服务版提供（端口 6379），连不上后端拒绝启动。

## 三、快速开始

### 方式一：一键启动（Windows）

双击项目根目录的 `start.bat`，脚本会依次完成：环境检查（Python / Node）→ 安装前后端依赖 → 初始化数据库 → 检查 Redis 服务在 6379 监听 → 启动后端(5109)与前端(5108) → 自动打开浏览器。Redis 未运行时后端会被跳过，先在 services.msc 里启动 Redis 服务再重跑。

### 方式二：手动启动

```bash
# 0. 建库（必须先手动创建，ORM 只能建表）
#    CREATE DATABASE campustalk DEFAULT CHARACTER SET utf8mb4 DEFAULT COLLATE utf8mb4_0900_ai_ci;

# 1. 后端
cd backend
copy .env.example .env      # 填入本机 MySQL 密码（DATABASE_URL），Redis 地址可用默认 REDIS_URL
python -m pip install -r requirements.txt
python init_db.py           # 幂等：建表 + 补列 + 预置演示账号
# 前置：Redis 服务已启动，否则 uvicorn 启动即报错退出
python -m uvicorn app.main:app --host 127.0.0.1 --port 5109

# 2. 前端（另开一个终端）
cd frontend
npm install
npm run dev
```

## 六、三种会话形态（统一会话抽象）

私聊 / 群聊 / 频道共用同一套 `conversation` + `conversation_member` + `message` 模型，差异只有三行：

| 需求点 | 私聊 single | 群聊 group | 频道 channel |
|---|---|---|---|
| 加入方式 | 双方成为好友后自动成立 | 群主邀请，或申请后群主 / 管理员同意 | **任何人免审直接加入** |
| 历史对新成员 | 全部可见 | **由群主配置**（全部 / 加入后 / 最近 N 条） | 全部可见 |
| 置顶能力 | 不支持 | 不支持 | **频道管理可置顶帖子 / 话题帖** |

| 权限 | 私聊 | 群聊 | 频道 |
|---|---|---|---|
| 谁能发言 | 双方 | 成员 | 成员（**免审进入 ≠ 免审发言**） |
| 谁能改名称头像 | — | 群主 / 管理员 | 创建者 / 管理员 |
| 谁能移除成员 | — | 群主 / 管理员 | 创建者 / 管理员 |
| 能否退出 | 删好友即消失 | 可退群 | 可退出 |

除上表所列差异外，消息收发、历史拉取、富媒体、撤回、未读统计等逻辑完全一致，由同一套代码实现。

## 七、核心设计原则

1. **消息先落库再推送**——`services/message_service.save_and_push` 是唯一入口；WebSocket 断开时消息仍在库里，刷新即补齐，这是「消息不丢」的全部保证。
2. **WebSocket 只搬运**——不做业务判断、不直接写库，一律转交服务层；机器人也以特殊发送者身份走同一条链路。
3. **文件只存 URL**——数据库只存 `/uploads/...`、文件名与大小，二进制绝不进库、绝不进 WS 帧。
4. **前端不持有业务规则**——所有校验与权限以后端为准，前端只展示拒绝理由。
5. **权限边界在接口层**——`require_admin` 才是真正的安全边界，前端隐藏入口与路由守卫只是体验层。
6. **账号禁用三处同时生效**——登录接口、鉴权依赖、WebSocket 握手，缺一处就会出现「禁用后仍能收发消息」。
7. **每个表只有一个域能写**——跨域判断必须问所属域，防止后期代码互相打架。
8. **隐私最小化**——加好友仅支持用户名精确检索（昵称 / 学号不可搜）；管理员不可浏览任意聊天记录，只能看到被举报的那一条；学号证明材料存私密目录，出审核结论后即删除原件。

## 九、范围外与演示边界

**功能范围外**：音视频通话、朋友圈动态、支付红包、端到端加密、原生移动端、扩列式陌生人匹配、按班级自动建群、审批 / 打卡 / 日程、已读回执、离线推送、多端同步；「禁言」为后期项。

**部署边界（强制）**：仅在**本机 `localhost`** 运行，不购买域名、不做 ICP 备案、不做内网穿透、不对外提供服务。这是内容合规风险可控的前提——一旦对外提供服务，平台性质与运营者责任随之改变。
